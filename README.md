# 设计标书编写工具（Bid Design Writer）

> 基于 Claude Code Skill 的建筑设计技术标书智能编写助手

## 一、项目概述

本工具是一个运行在 Claude Code 环境中的 **Skill（技能）**，专注于解析建筑设计类招标文件、提取关键信息，并基于评分标准自动编写建筑设计技术标书。AI 全权起草文字初稿，设计师仅需对事实、专业结论和履约能力进行审核确认。

### 1.1 核心定位

- **专精领域**：建筑设计技术标书（方案设计、方案深化、施工图设计）
- **不适用范围**：工程勘察、市政、景观、造价、监理、施工组织等非建筑设计内容
- **交付边界**：AI 生成文字方案 + 绘图提示词 + 专业图纸需求清单；不生成实际图片或工程图纸

### 1.2 适用场景

| 标书类型 | 适用性 | 说明 |
|----------|--------|------|
| 建筑方案设计标 | ✅ 完全适用 | 从前期分析到方案生成到技术图纸全流程 |
| 方案深化设计标 | ✅ 完全适用 | 聚焦方案优化、专业深化、技术措施 |
| 施工图设计大纲 | ✅ 完全适用 | 侧重质量闭环、进度管控、专业协同 |
| 全过程工程咨询标（设计板块） | ✅ 部分适用 | 仅编写设计工作实施方案板块（约25-35页） |
| 纯工程勘察/监理/造价标 | ❌ 不适用 | 非建筑设计范畴 |

## 二、核心工作流

本工具采用严格的**两阶段工作流**，必须按顺序执行，不可跳过阶段一直接编写。

```
阶段一：信息提取  →  用户确认  →  阶段二：设计方案编写
   (提取)           (CHECKPOINT)        (编写)
```

### 2.1 阶段一：信息提取

从招标文件中提取以下四类信息（每项必须注明出处）：

| 信息类别 | 核心内容 |
|----------|---------|
| 项目基本信息 | 项目名称/编号/招标方/预算/工期/规模等 |
| 建筑设计方案要求 | 设计范围/深度/专业/规范/成果清单/图纸要求 |
| 评分标准分析 | 评分项/分值/满分条件/得分要点/废标条款/暗标要求 |
| 标书制作规范 | 装订/份数/格式/字体/签字盖章等 |

**产出物**：`{项目名称}_招标文件信息提取.md`

### 2.2 阶段二：设计方案编写

基于阶段一确认的信息，按评分标准编写完整的技术标书：

1. 建立招标约束模型 → 2. 评分责任切分 → 3. 动态生成目录 → 4. 编写正文 → 5. 硬编码审计 → 6. 交付终检

**产出物**：
- `{项目名称}_设计方案.md`（必存源稿，含大纲 + 正文 + 图文需求）
- `{项目名称}_图文证据与图纸需求.md`（招标文件触发时）
- `{项目名称}_标书制作规范.md`（招标文件有制作规范时）


### 3.1 文件说明

#### SKILL.md — 核心定义文件

定义了两阶段工作流的完整规则体系，包括：

- **两阶段 CHECKPOINT 机制**：阶段一必须经用户确认才能进入阶段二
- **参考材料权威性分级**：A 级（招标文件/澄清）> B 级（已确认方案）> C 级（历史投标文件/模板）
- **冲突阻断机制**：A 级与 B/C 级数据冲突时建立冲突清单，仅使用 A 级值
- **实体污染审计**：读取历史材料时自动扫描跨项目残留的专有名称和数值
- **动态编排规则**：不预设目录模板，由当前项目的评分/范围/成果要求动态生成章节
- **图文证据判定**：仅当招标文件明确要求时才输出绘图提示词或制图需求
- **硬编码审计**：交付前逐项核查每章节/数值/措施/承诺是否有触发依据
- **交付终检清单**：覆盖评分/废标/暗标/事实/内容/图文/文件 7 个维度的强制核验

#### references/ 目录

| 文件 | 用途 | 页数参考 | 适用标书类型 |
|------|------|---------|-------------|

## 四、核心设计原则

### 4.1 评分导向

- 每个章节开头标注 `> 📌 本章响应评分项：...`
- 非建筑设计评分项仅标注边界，不编写正文
- 高分值项优先分配篇幅和技术深度

### 4.2 禁止空话

禁用「采用先进技术」「科学管理」「精心设计」等无实质内容的口号。每句话必须包含可验证的具体信息：

| 禁用词 | 替换要求 |
|--------|---------|
| 采用先进技术 | 采用 **{具体技术名称}**，实现 **{具体指标}** |
| 科学管理 | 按 **{标准编号}** 建立管理体系，含 **{N}** 个控制节点 |
| 精心设计 | 针对 **{具体场景}**，在 **{具体环节}** 采取 **{具体措施}** |

### 4.3 暗标合规

如招标文件要求暗标评审（盲评），自动执行以下规则：
1. 不出现投标人名称、简称、英文缩写
2. 过往项目名称替换为通用描述（如「某省级政务云项目」）
3. 不出现获奖、专利、资质等可追溯信息
4. 人员姓名替换为角色描述（如「项目负责人」）

### 4.4 图文策略驱动

图片处理方式（占位符 / AI 绘图提示词）**唯一依据**是招标文件中的图纸要求分类：
- 专业工程图纸（平立剖/分析图等）→ `[图片占位]` + 制图需求
- 其他图纸（效果图/鸟瞰图/透视图等）→ 自生成绘图提示词
- 招标未要求的图纸 → 不输出

### 4.5 模板不预设

模板文件仅作为章节组织**参考**，不是默认目录。实际章节名称、数量、顺序完全由当前项目的评分项、服务范围和成果要求动态生成。

## 五、可复用模块体系

`references/可复用模块卡片.md` 沉淀了从真实中标标书中提取的 9 个可复用方法模块。每个模块包含：适用条件、不适用条件、解决的评分问题、最低交付物、关键控制点和不可迁移内容。

### 5.1 模块分类

| 分类 | 模块 | 来源项目类型 |
|------|------|-------------|
| 住宅方案深化 | 滨水/景观资源 + 场地高差方案深化 | 住宅 |
| 住宅方案深化 | 地下室六联动优化 | 住宅 |
| 住宅方案深化 | 立面落地与成本协同 | 住宅 |
| 住宅方案深化 | 户型优化评分表达 | 住宅 |
| 施工图设计大纲 | 施工图质量闭环 | 住宅 |
| 施工图设计大纲 | 施工图进度、成本与服务联动 | 住宅 |
| 教育建筑设计 | 山地/滨水场地深化 | 职教校园 |
| 教育建筑设计 | 既有校园风貌延续与低碳立面 | 职教校园 |
| 教育建筑设计 | 效果图硬约束与 A3 技术标页组 | 职教校园 |

### 5.2 模块调用门槛

必须**三项同时匹配**才能调用模块中的去项目化方法：
1. 当前招标条款匹配
2. 当前项目资料匹配
3. 当前责任边界匹配

任一项不满足即不得调用，且模块名称、章节、图名、视点、专业措施和承诺均不得出现在输出中。

> ⚠️ 所有模板和模块卡片均不包含具体单位名称、项目名称或可识别信息——仅保留表达结构、控制流程和版式方法。

## 六、规范引用与扩展性

### 6.1 真实投标反向拆解

从历史中标标书中提取四类可复用资产（仅在用户要求复盘/沉淀时执行）：
- **评分交付矩阵**：每个评分项的证据组合（文字/图文/表格/节点/页组）
- **视觉资产矩阵**：图名、表达目的、版式信息、服务评分项和可复用条件
- **措施拆解表**：质量/进度/成本/服务措施按五要素拆解（控制对象→触发节点→责任角色→输出记录→闭环方式）
- **可复用模块卡**：去项目化后按「三项匹配」条件写入模块库

### 6.2 知识资产沉淀

每个项目完成后，以下产物自然形成可复用的知识资产：

| 资产 | 复用场景 |
|------|---------|
| 招标约束模型 | 复核下一项目的提取字段（不复用业务结论） |
| 评分责任与证据编排 | 复核评分映射、责任边界和证据颗粒度 |
| 设计方案正文 | 仅反向提取结构、控制流程和表达方法 |
| 图文证据判定 | 复核何时需要视觉或制图支持（不复用图名/视点） |
| 可复用模块卡 | 经人工复核后补充到 `references/可复用模块卡片.md` |

## 七、使用方式

### 7.1 前置条件

- Claude Code 运行环境
- 建筑设计类招标文件（PDF/Word/纯文本）

### 7.2 调用方式

在 Claude Code 中，通过 Skill 机制自动触发：

```
# 直接提及建筑设计标书相关关键词
"帮我写这个医院项目的设计方案标书"
"分析这份招标文件的评分标准"

# 或指定 Skill 名称
/bid-design-writer [招标文件路径]
```

触发关键词：建筑设计标书、设计方案投标、方案深化设计、施工图设计大纲

### 7.3 典型工作流程

```
用户提供招标文件
    ↓
阶段一：AI 提取四类信息并保存
    ↓
🛑 用户确认提取结果
    ↓
阶段二：AI 编写完整标书初稿并保存
    ↓
设计师审核事实、专业结论、图纸
    ↓
最终提交
```
